## P2 - 项目定位

**一句话定位**：将校园二手交易、社区交流、活动组织、实时聊天聚合于一个平台。

| 传统方式 | EasyCampus |
|----------|------------|
| 二手群、社团群、活动群各自为战 | 一个平台聚合所有校园需求 |
| 信息散落在微信群/QQ群/贴吧 | 信息流统一呈现，分类清晰 |
| 交易沟通需加好友、切换App | 站内一键私聊，WebSocket实时通信 |
| 社团交易无统一管理 | 交易组织模块，成员审核+审计日志 |

## P7 - 数据库核心设计

**数据库规模**：21张表，覆盖用户、交易、社交、组织、通知全业务

**核心ER关系**：

```
  users ──1:N──→ products ──1:N──→ product_comments
    │              │
    │              └──1:N──→ favorites (PRODUCT类型)
    │              │
    │              └──1:N──→ orders
    │
    ├──1:N──→ posts ──1:N──→ post_comments (嵌套回复)
    │              │
    │              └──1:N──→ favorites (POST类型)
    │
    ├──1:N──→ chat_conversations ──1:N──→ chat_messages
    │
    ├──1:N──→ user_likes (POST / COMMENT / PRODUCT 多目标)
    ├──1:N──→ user_follows (关注关系)
    ├──1:N──→ user_behaviors (行为记录)
    ├──1:N──→ notifications (通知)
    │
    └──1:N──→ trade_organizations ──1:N──→ org_members
                                            org_join_requests
                                            org_invitations
                                            org_audit_logs
```

**设计亮点**：
- `user_likes` 表通过 `target_type` 字段支持帖子/评论/商品三种点赞目标，避免为每种类型建表
- `favorites` 表同样通过 `target_type` 统一管理商品和帖子收藏
- 帖子评论、商品评论均支持 `parent_id` 嵌套回复

## P8 - 创新点一：多功能深度融合联动

**核心观点**：不是简单堆砌功能，而是模块间形成有机联动闭环。

**功能联动关系图**：

```
                         ┌──────────────┐
                         │   信息流推荐   │
                         │  (用户行为分析) │
                         └──────┬───────┘
                                │ 驱动
                                ▼
   ┌──────────┐    行为数据    ┌──────────┐    行为数据    ┌──────────┐
   │ 社区帖子  │ ───────────→ │  用户行为  │ ←─────────── │ 二手商品  │
   └────┬─────┘              └─────┬─────┘              └────┬─────┘
        │                          │                         │
        │ 评论/点赞                │ 评论/点赞               │ 聊天
        ▼                          ▼                         ▼
  ┌──────────┐             ┌──────────────┐          ┌──────────┐
  │ 社交互动  │ ←─────────→ │   实时聊天     │ ←──────→ │ 交易沟通  │
  │(关注/收藏)│             │  (WebSocket)  │          │(私聊议价) │
  └──────────┘             └──────────────┘          └──────────┘
                                    │
        ┌───────────────────────────┤
        ▼                           ▼
  ┌──────────┐               ┌──────────┐
  │ 校园活动  │               │ 交易组织  │
  │(报名/追踪)│               │(社团交易圈)│
  └──────────┘               └──────────┘
```

**关键联动链路举例**：
1. **浏览 → 沟通**：看到商品/帖子 → 一键私聊作者 → WebSocket实时对话
2. **浏览 → 推荐**：用户行为数据 → 驱动信息流推荐 → 更精准的内容呈现
3. **社交 → 交易**：关注卖家 → 新商品通知 → 促进复购
4. **组织 → 交易**：社团内部交易圈 → 信任背书 → 交易更安全
5. **活动 → 社交**：活动帖子 → 报名互动 → 建立社交关系

## P9 - 创新点二：信息流推荐 + 广告系统

### 信息流推荐
- **数据来源**：`user_behaviors` 表记录用户的浏览、点赞、收藏、搜索行为
- **推荐策略**：混合内容流（帖子 + 商品），综合用户兴趣标签和热门内容
- **作用**：首页 Feed 个性化呈现，提升内容匹配度

### 广告系统
- **广告创建**：帖子发布者可选择将帖子升级为广告
- **四档曝光套餐**：

| 套餐 | 曝光倍数 | 适用场景 |
|------|---------|---------|
| 体验版 | 2x | 初次尝试 |
| 基础版 | 5x | 普通推广 |
| 热门版 | 10x | 重点推广 |
| 爆款版 | 20x | 全力曝光 |

- **支付流程**：套餐选择 → 模拟支付 → 广告生效

### 商业闭环
`用户发布内容 → 选择推广 → 支付套餐 → 获得更高曝光 → 促成交易/互动`

## P10 - 创新点三：交易组织（社团交易圈）

**场景痛点**：校园内社团/班级内部有闲置交易需求，但公开二手平台缺乏信任，微信群混乱难管理。

**解决方案**：交易组织模块

**核心功能流程**：

```
         创建组织
            │
    ┌───────┴───────┐
    ▼               ▼
  邀请加入        申请加入
    │               │
    ▼               ▼
  发送邀请码      提交留言申请
    │               │
    └───────┬───────┘
            ▼
        审核管理
        (通过/拒绝)
            │
            ▼
        成员管理
   (角色/移除/离开)
            │
            ▼
        操作审计日志
     (所有变更可追溯)
```

**差异化价值**：
- 通用二手平台没有的组织管理功能
- 校园熟人社交，交易信任度更高
- 完整的审核+审计机制，保障组织安全

## P11 - WebSocket 实时通信

**技术选型**：Spring Boot WebSocket + 前端原生 WebSocket API

**实现内容**：
- **私聊消息实时推送**：发送方 → 服务端转发 → 接收方即时收到
- **未读计数实时更新**：会话列表中的红点标记即时刷新
- **在线状态检测**：判断对方是否在线
- **商品卡片内联**：聊天中可嵌入商品信息预览

**消息流转示意**：


## P12 - 分片上传 + Docker 部署

### 大文件图片分片上传
- **问题**：校园网络环境下大图片上传容易失败
- **方案**：前端将大文件切片(chunk) → 逐片上传 → 后端合并(merge)
- **优势**：支持断点续传思路、上传进度可视化、单文件大小不受服务器限制

```
  大文件 → 切片 → [chunk1] [chunk2] ... [chunkN]
                      │       │           │
                      ▼       ▼           ▼
                   后端逐片接收，全部完成后 merge 为完整文件
```

### Docker 容器化部署
- **Docker Compose**：前后端分别容器化，Nginx 反向代理统一入口
- **环境隔离**：`application-dev.yml` / `application-prod.yml` 开发与生产配置分离
- **一键部署**：`./deploy.sh "commit信息"` 自动完成编译验证 → git push → SSH远程拉取 → Docker构建部署

**部署流程**：

```
 本地编码修改 → 编译验证 → git push → SSH登录服务器
                                         │
                                         ▼
                                   git pull 拉取代码
                                         │
                                         ▼
                              Docker Compose 构建+部署
                              (docker compose build && up -d)
```
