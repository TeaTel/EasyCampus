# 易校 EasyCampus 项目验收报告

---

## 1、系统概述

### 1.1 系统应用背景

在当今校园生活中，学生的日常需求涵盖二手交易、社区交流、活动组织和即时通讯等多个方面。然而，传统方式存在以下痛点：

- 二手交易、社团交流、活动组织各自分散在不同微信群、QQ群中，信息碎片化严重
- 交易沟通需要频繁添加好友、切换多个应用
- 缺乏统一的校园信息聚合平台
- 社团内部交易缺乏信任背书和规范管理

为解决上述痛点，我们开发了"**易校 EasyCampus**"——一款面向高校学生的一站式校园综合社交与交易平台。平台将校园二手交易、社区交流、活动组织、实时聊天四大核心需求聚合于一体，为在校学生提供便捷、安全、高效的校园生活服务。

### 1.2 系统功能简介

易校 EasyCampus 围绕校园生活场景，提供以下核心功能：

| 功能模块 | 说明 |
|---------|------|
| 用户系统 | 注册、登录、JWT认证、密码重置、个人信息管理、校区设置 |
| 二手交易 | 商品发布（多图+分类+价格）、浏览、搜索筛选、收藏、评论、一键私聊卖家 |
| 社区帖子 | 帖子发布（讨论/展示/求助/活动）、评论互动（嵌套回复）、点赞、关注、加精置顶 |
| 校园活动 | 活动发布（时间/地点/联系方式）、状态追踪（即将开始/进行中/已结束）、报名管理 |
| 实时聊天 | WebSocket 即时通信、表情选择器、商品卡片内联、会话管理 |
| 交易组织 | 创建组织、邀请/申请加入、成员管理、审核机制、操作审计日志 |
| 信息流推荐 | 首页混合内容流（帖子+商品）、基于用户行为的个性化推荐 |
| 广告系统 | 帖子推广、四档曝光套餐、模拟支付 |
| 全局搜索 | 支持帖子/商品/用户搜索、分类Tab筛选 |
| 通知系统 | 点赞、评论、关注等行为通知推送 |

### 1.3 用户类别

| 用户类别 | 说明 | 权限 |
|---------|------|------|
| 普通用户 | 平台主要使用者（在校学生） | 浏览内容、发布商品/帖子、聊天互动、加入组织等 |
| 组织管理员 | 社团/班级交易组织的创建者 | 管理成员、审批申请/邀请、查看审计日志 |
| 系统管理员 | 平台运营维护人员 | 帖子加精/置顶管理、广告审核等 |

### 1.4 系统意义

- **便捷性**：一个平台聚合校园交易、社交、活动、通讯需求，无需在多个应用间切换
- **安全性**：组织模块的审核+审计机制、JWT认证保障用户信息安全
- **校园专属**：校区标签、交易组织贴合校园场景，基于熟人关系的交易信任度更高
- **智能化**：基于用户行为的信息流推荐，提升内容匹配度和用户体验

### 2.2 安装配置步骤

#### 2.2.1 本地开发环境搭建

**（1）克隆项目**

```bash
git clone <仓库地址>
cd Campus-Community-AppV1.2-2.0-main
```

**（2）数据库初始化**

- 创建 MySQL 数据库 `campus_market_dev`
- 执行 `backend/src/main/resources/schema-mysql.sql` 建表
- 执行 `backend/src/main/resources/data-mysql.sql` 导入初始数据（含80个测试用户）
- 按需执行 `migration-v2.sql` 至 `migration-v7-notifications.sql` 版本迁移脚本

**（3）后端启动**

```bash
./backend/mvnw -f backend/pom.xml spring-boot:run -Dspring-boot.run.profiles=dev
```

后端默认运行在 `http://localhost:8080`，开发环境下 Knife4j API 文档可通过 `/doc.html` 访问。

**（4）前端启动**

```bash
cd frontend
npm install
npm run dev
```

前端默认运行在 `http://localhost:3000`，会通过 Vite 代理将 `/api` 请求转发到后端 8080 端口。

#### 2.2.2 生产环境部署

项目采用 Docker Compose + Nginx 容器化部署方案，服务器地址：`root@154.12.90.231`，域名：`https://c2cmarket.store`。

**一键部署命令**：

```bash
./deploy.sh "提交信息"
```

自动执行：编译验证 → git push → SSH 远程 git pull → Docker 构建部署。

**手动部署步骤**：

```bash
# 1. 本地编译验证
cd frontend && npx vite build
cd ../backend && ./mvnw -f backend/pom.xml compile

# 2. 推送代码
git push

# 3. SSH 登录服务器
ssh root@154.12.90.231
cd /opt/campus_platform
git pull

# 4. Docker 构建部署
docker compose -f docker-compose.prod.yml build backend
docker compose -f docker-compose.prod.yml up -d
```

## 3、系统功能介绍

### 3.1 用户认证模块

**功能描述**：支持用户注册、登录、密码重置和JWT认证。

**操作步骤**：
1. 访问首页，点击"登录"按钮进入登录页
2. 输入用户名和密码完成登录（可勾选"记住我"）
3. 新用户点击"注册"链接进入注册页，填写用户名/昵称/邮箱/密码并同意协议
4. 忘记密码时进入找回密码页，通过邮箱验证码三步流程重置密码
5. 登录后 JWT Token 存储在 localStorage，请求自动携带认证信息

**涉及页面**：`/login`、`/register`、`/forgot-password`

---

### 3.2 首页信息流

**功能描述**：展示混合内容信息流（帖子+商品），支持标签筛选和个性化推荐。

**操作步骤**：
1. 打开应用即进入首页，展示推荐内容的瀑布流
2. 通过顶部标签栏切换内容分类（关注/发现/校区）
3. 点击"全部"下拉选择特定内容类型筛选
4. 向下滚动自动加载更多内容（无限滚动）
5. 点击帖子卡片跳转帖子详情，点击商品卡片跳转商品详情，点击活动卡片跳转活动详情

**涉及页面**：`/`

---

### 3.3 二手商品交易

**功能描述**：完整的二手商品交易流程，涵盖发布、浏览、搜索筛选、详情查看、收藏评论和交易沟通。

**操作步骤**：
- **发布商品**：点击底部"+"发布按钮 → 选择"发布交易" → 上传商品图片（支持多图） → 填写标题/描述/价格/分类/成色/交付方式/交易地点 → 确认提交
- **浏览商品**：进入商品列表页 → 使用搜索框搜索 → 选择排序方式（综合/价格/最新）→ 选择分类标签筛选
- **查看详情**：点击商品卡片 → 查看图片画廊/价格/描述/卖家信息 → 可点赞/收藏/评论
- **联系卖家**：在商品详情页底部点击"聊一聊"按钮，进入一对一聊天室与卖家沟通议价

**涉及页面**：`/products`、`/products/:id`、`/products/create`、`/my-products`、`/favorites`

---

### 3.4 社区帖子

**功能描述**：社区交流模块，支持发布帖子（讨论/展示/求助/活动四种类型），评论互动，点赞关注。

**操作步骤**：
- **浏览帖子**：进入社区页面，切换"推荐/帖子/热门"三个Tab查看不同内容
- **发布帖子**：点击发布按钮 → 选择帖子类型（讨论/展示/求助/活动） → 上传图片 → 填写标题和内容 → 添加标签和校区标签 → 发布
- **帖子详情**：点击帖子卡片 → 查看完整内容/图片/标签 → 点赞/收藏/关注作者 → 发表评论或回复他人评论（支持嵌套回复）
- **帖子管理**：在"我的"→"商品与帖子"中查看自己发布的帖子，可删除

**涉及页面**：`/community`、`/community/posts/:id`、`/community/posts/create`

---

### 3.5 实时聊天

**功能描述**：基于 WebSocket 的即时通信，支持私聊和商品信息共享。

**操作步骤**：
1. 进入消息列表页查看所有会话（含最后消息、未读数、在线状态）
2. 点击某个会话进入聊天室
3. 在输入框输入文字，点击发送按钮发送消息
4. 点击表情按钮选择表情符号
5. 从商品详情页"聊一聊"进入时，聊天中自动嵌入商品预览卡片
6. 点击对方头像可查看联系人资料

**涉及页面**：`/messages`、`/chat/:userId`

---

### 3.6 校园活动

**功能描述**：校园活动发布、浏览、报名和状态追踪。

**操作步骤**：
1. 进入活动列表页，切换"即将开始/进行中/已结束"三个Tab查看不同状态的活动
2. 点击活动卡片进入活动详情，查看活动封面/时间/地点/联系方式/标签
3. 点击"我要报名"按钮报名参加活动
4. 在"我的活动"页面管理自己创建的活动

**涉及页面**：`/activities`、`/activities/:id`、`/my-activities`

---

### 3.7 交易组织（社团交易圈）

**功能描述**：为社团/班级提供专属交易组织功能，支持成员管理和审核机制。

**操作步骤**：
1. **创建组织**：进入创建组织页 → 三步表单（基本信息→详细资料→确认提交）→ 选择组织类型和加入方式
2. **发现组织**：在发现组织页搜索和浏览已有组织 → 申请加入
3. **管理组织**：组织详情页 → 管理面板 → 查看申请列表 → 审批通过/拒绝 → 成员管理（角色分配/移除） → 邀请新成员 → 查看操作审计日志
4. **我的组织**：查看已加入的组织列表和审核状态

**涉及页面**：`/orgs/create`、`/orgs/discover`、`/orgs/:id`、`/orgs/my`

---

### 3.8 个人中心

**功能描述**：用户个人信息管理、数据统计、功能导航入口。

**操作步骤**：
1. 进入个人中心查看头像/昵称/ID/简介/发布和收藏统计
2. 点击头像上传更换头像（支持图片上传）
3. 点击菜单进入各功能页面：商品与帖子管理、我的收藏、我的活动、设置
4. 未登录状态下显示登录引导，引导用户登录

**涉及页面**：`/profile`、`/settings`、`/users/:id`、`/address`、`/campus`

---

### 3.9 全局搜索

**功能描述**：支持帖子、商品、用户三类内容的全局搜索。

**操作步骤**：
1. 在任意页面顶部搜索框输入关键词，点击搜索跳转搜索页
2. 在搜索页通过 Tab 切换筛选类型（全部/帖子/商品/用户）
3. 点击搜索结果跳转对应详情页

**涉及页面**：`/search`

## 4、系统程序结构

### 4.1 技术方案概述

本项目采用**前后端分离**架构，前端基于 Vue 3 生态构建 SPA 单页应用，后端基于 Spring Boot 3 构建 RESTful API 服务，通过 HTTP 协议和 WebSocket 协议进行通信。

**技术栈**：

| 层面 | 技术 | 版本 |
|------|------|------|
| 前端框架 | Vue 3 (Composition API + script setup) | 3.x |
| 前端构建 | Vite | 5.x |
| 前端路由 | Vue Router | 4.x |
| 前端状态管理 | Pinia | - |
| HTTP 请求 | Axios | - |
| 实时通信 | 原生 WebSocket | - |
| XSS 防护 | DOMPurify | - |
| 后端框架 | Spring Boot | 3.3.5 |
| 安全认证 | Spring Security + JWT | - |
| 持久层 | MyBatis | 3.0.3 |
| 数据库 | MySQL | 8.0 |
| 缓存 | Redis + Caffeine | - |
| 邮件服务 | JavaMailSender | - |
| 图片处理 | Thumbnailator | - |
| API 文档 | Knife4j (Swagger) | - |
| 容器化部署 | Docker + Docker Compose | - |
| 反向代理 | Nginx | - |

### 4.3 数据库设计

数据库采用 MySQL 8.0，共设计 **21 张数据表**，覆盖用户、交易、社交、组织、通知全业务。

**核心数据表清单**：

| 表名 | 说明 | 关键关系 |
|------|------|---------|
| users | 用户表 | 用户基础信息 |
| products | 商品表 | 关联 users |
| product_comments | 商品评论表 | 关联 products, users |
| posts | 帖子表 | 关联 users |
| post_comments | 帖子评论表 | 关联 posts, users |
| categories | 分类表 | 商品/帖子分类 |
| chat_conversations | 聊天会话表 | 关联 users |
| chat_messages | 聊天消息表 | 关联 chat_conversations |
| favorites | 收藏表 | target_type 统一 POST/PRODUCT |
| user_likes | 点赞表 | target_type 统一多目标 |
| user_follows | 关注关系表 | 关联 users |
| user_behaviors | 用户行为表 | 推荐引擎数据源 |
| notifications | 通知表 | 关联 users |
| trade_organizations | 交易组织表 | 关联 users |
| org_members | 组织成员表 | 关联 organizations, users |
| org_join_requests | 加入申请表 | 关联 organizations, users |
| org_invitations | 邀请表 | 关联 organizations, users |
| org_audit_logs | 审计日志表 | 关联 organizations, users |
| advertisements | 广告表 | 关联 posts |
| verification_codes | 验证码表 | 关联 users |
| orders | 订单表 | 关联 products, users |

**设计亮点**：
- `user_likes` 表通过 `target_type` 字段统一支持帖子/评论/商品三种点赞目标
- `favorites` 表通过 `target_type` 统一管理商品和帖子收藏
- `post_comments` 和 `product_comments` 均支持 `parent_id` 嵌套回复

### 5.2 采用技术方法评价

| 技术/工具 | 使用场景 | 评价 |
|----------|---------|------|
| Vue 3 Composition API | 前端整体框架 | **优点**：`<script setup>` 语法简洁、组合式 API 复用性高、响应式系统高效；33个页面和14个组件的开发验证了其大规模应用的可行性 |
| Spring Boot 3 + MyBatis | 后端整体框架 | **优点**：自动配置简化开发，MyBatis 灵活的 SQL 编写能力适合复杂查询场景；**不足**：Service 层部分实现直接依赖 Mapper，分层不够严格，可维护性有待提升 |
| JWT + Spring Security | 用户认证与权限控制 | **不足**：Security 配置未正确限制接口权限，所有 `/api/**` 为 permitAll，JWT 认证虽然生效但权限控制的优势未能发挥 |
| WebSocket | 实时聊天 | **优点**：原生 WebSocket 实现简单直接；**不足**：消息推送的可靠性和实时性存在缺陷，缺少消息发送失败重试机制 |
| Pinia 状态管理 | 全局认证/通知状态 | **优点**：API 简洁，与 Vue 3 结合良好，相比 Vuex 更轻量 |
| Docker + Docker Compose | 容器化部署 | **优点**：一键部署脚本显著简化上线流程，环境隔离避免"在我机器上能跑"的问题 |
| 分片上传 | 大文件图片上传 | **优点**：解决了校园网环境下大图片上传失败的问题，支持进度可视化 |

**总体评价**：技术选型合理，Vue 3 + Spring Boot 3 的前后端分离架构成熟稳定。Docker 容器化部署和分片上传两点技术方案体现了对实际部署环境和用户体验的考量。不足之处在于权限控制配置不当、部分后端业务逻辑分层不严格。

### 5.3 收获与不足、改进措施

#### 主要收获

1. **前后端分离架构的完整实践**：从项目搭建到线上部署，完整经历了 Vue 3 + Spring Boot 3 的前后端分离开发流程，掌握了路由守卫、JWT 认证、跨域配置、API 版本管理等关键技术点。

2. **实时通信技术经验**：通过 WebSocket 实现聊天功能，理解了长连接管理、消息推送、在线状态检测等实时通信的核心概念。

3. **复杂业务建模能力提升**：如交易组织的审核+审计机制、点赞收藏的多目标统一设计、嵌套评论的递归查询等，锻炼了数据库设计和复杂业务逻辑编排的能力。

4. **Docker 容器化部署**：掌握了 Docker Compose + Nginx 反向代理的部署方案，理解了 CI/CD 的基本流程。

5. **工程化思维**：通过33个页面、14个组件、16个API模块的开发，积累了组件化、模块化的工程实践经验。

#### 主要不足

| 类别 | 问题描述 | 改进措施 |
|------|---------|---------|
| 安全性 | Security 配置所有接口 permitAll，权限控制缺失 | 完善 User 实体 role 字段，修复 SecurityConfig 路径权限配置，区分公开/认证/管理员接口 |
| 安全性 | 组织页面、发布页面路由守卫遗漏，未登录可访问 | 排查并修复 router/index.js 白名单配置，将需要认证的路由加入守卫拦截 |
| 功能完整性 | 密码重置未接入邮件服务，为"空壳"功能 | 接入 JavaMailSender 实现验证码发送和校验流程 |
| 功能完整性 | 活动报名接口不持久化数据 | 完善 ActivityController 中 joinActivity/cancelJoin 的数据持久化逻辑 |
| 功能完整性 | 圈子功能仅占位，尚未实现 | 后续迭代补充圈子详情页内容和功能 |
| 代码质量 | Controller 层直接注入 Mapper 处理业务逻辑 | 将业务逻辑下沉至 Service 层，保持 Controller 层职责单一 |
| 代码质量 | 硬编码颜色值，与 design-system.css 变量不一致 | 统一使用 CSS 变量引用 |
| 代码质量 | 存在 console.log 残留和事件监听未清理 | 移除调试日志，在 onUnmounted 中清理定时器和事件监听 |
| 用户体验 | 聊天消息非实时，无未读数徽章 | 排查 WebSocket 消息推送机制，补全未读数轮询和徽章展示 |
| 用户体验 | 收藏功能后端接口异常导致完全失效 | 排查 FavoriteController API 路径（/api/favorites 与 /api/v2/favorites 不一致问题），统一前后端接口 |
| 移动端适配 | 输入框被虚拟键盘遮挡，触摸漂移 | 使用 visualViewport API 监听键盘弹出，动态调整滚动位置；优化触摸事件处理 |
| 测试覆盖 | 缺乏自动化单元测试和集成测试 | 引入 JUnit + Mockito 编写后端单元测试，引入 Cypress/Playwright 编写前端 E2E 测试 |

#### 后续改进方向

1. **安全加固**：完善角色权限控制（USER/ADMIN），修复路由守卫遗漏，生产环境禁用数据库测试接口
2. **功能补全**：收藏功能修复、活动报名数据持久化、密码重置邮件接入、圈子详情页开发
3. **体验优化**：聊天实时性修复、未读数徽章、移动端输入遮挡修复、图片预览弹窗
4. **性能优化**：推荐服务 N+1 查询优化、Feed 深度分页改为游标分页
5. **长效发展**：微信小程序端、AI推荐算法增强、实名校园认证
